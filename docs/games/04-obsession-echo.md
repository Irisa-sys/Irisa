# 04 执念回音壁 (The Obsession Echo)

slug: `echo`

## 一句话定义

这是一个延迟发生的承诺装置：玩家在清醒、笃定的时刻封存一句具体承诺；系统不日常打卡、不展示进度，也不催促。只有当病理报告连续证明玩家正在偏离生活时，承诺才会以一次不可略过的全屏回音回来，要求玩家重新认领或正式放下它。

它不是待办清单、习惯追踪器或羞辱弹窗。它只负责让玩家和过去的自己完成一次诚实的对话。

## 设计目标与边界

| 要保留 | 明确不做 |
| --- | --- |
| 一次立誓、长期沉默、一次强打断的戏剧张力 | 誓言列表、连续打卡、倒计时、完成率、排行榜 |
| 以玩家主动提交的病理事实作为唯一触发依据 | 通过在线时长、访问记录或猜测行为触发 |
| 允许承诺被修订或终止，避免把旧目标变成惩罚 | 强迫续约、反复触发同一条已回应的誓言 |
| 原文最小暴露，除回音瞬间外不可见 | 在导航、总览、活动流或通知中泄露誓言内容 |

## 核心玩法

### 1. 立誓：把模糊愿望变成可被认出的原句

玩家从导航进入「立誓」页，写下一句 20–80 字的承诺。输入框只引导一句完整的话，例如：`在今年十月前，完成并公开我的作品集。`

提交前增加一个轻量的“具体性确认”：玩家选择一个承诺范围，而不是填写额外 KPI。

| 范围 | 含义 | 回音时的提问 |
| --- | --- | --- |
| 一次完成 | 有明确终点的作品、决定或行动 | “这件事还值得完成吗？” |
| 一段投入 | 某项持续学习、练习或生活改变 | “你还愿意把时间给它吗？” |
| 一个底线 | 不再做、必须守住的原则 | “这条底线还属于你吗？” |

点击「封存这句话」后，原文立刻从界面中抹去。页面只保留一次 3 秒的确认态：`已封存。它不会提醒你。它会在需要时回来。`

### 2. 沉默：系统刻意不制造日常任务

誓言进入休眠后，导航只显示一个低调的紫色封印点，不显示数量、状态和原文。玩家回到立誓页只能看到“已有一句话正在沉默中”，不能查看、编辑或删除。

这段空白是体验的一部分：病理游戏记录的是当下，回音壁保存的是过去的判断，二者不能被拼成一个供玩家优化的仪表盘。

### 3. 武装：只由病理事实触发

每收到 `pathology.report.issued` 后，回音域将该报告纳入最近 5 个“有病历”的日期窗口；定时任务每 6 小时重新评估一次。

P0 武装条件：

```text
存在 DORMANT 誓言
且最近 5 个有病历日期中 SEVERE_SLACK >= 3
且该誓言在本轮病理恶化周期内未被回音过
=> ARMED
```

无病历永不触发。缺失数据不等于失败，这既保护玩家，也避免系统根据行为猜测制造惊吓。

武装是静默的：不发 toast、不进活动流、不在立誓页暴露原因。后端写入 `echo:pending:{playerId}`，等待下一次宿主加载。

### 4. 回音：在任意工作台页面前发生的仪式

宿主壳层初始化时先请求 `GET /api/echo/pending`。若有待处理回音，路由内容不应先闪现；壳层直接覆盖全屏 `EchoInterrupt`，再建立回音流获取原文。

回音分三拍展开，时长短、不可跳过，但不使用音频自动播放：

1. **黑场（约 600ms）**：低频颗粒和一条微弱紫色扫描线，文案为“检测到一段未结的旧信号”。
2. **原句浮现（约 1.5s）**：誓言按短句逐段出现，页面不展示病历详情，只说明“近期记录显示你正在偏离这句话”。
3. **记忆校验**：原文淡出为模糊残影，玩家输入原句中的 2–4 个连续关键词。服务端校验通过后才进入结论页。

关键词不由前端预先下发。`pending` 仅返回 `oathId` 和所需词数；原文及校验策略只存在于触发流和服务端，避免直接从初始接口或页面状态中取到答案。

### 5. 结论：续约、改写或放下

校验通过后，玩家必须选择一项结论：

| 选择 | 玩家动作 | 状态与后果 |
| --- | --- | --- |
| 仍然有效 | 确认“我仍愿意为它负责” | 原誓言回到 `DORMANT`；记录本次回音，当前病理恶化周期内不再触发 |
| 改写后续约 | 写一句新的、更诚实的承诺并再次封存 | 旧誓言 `SUPERSEDED`，新誓言 `DORMANT`；保留私有审计关联，不向 UI 展示历史 |
| 正式放下 | 输入“我决定放下”确认 | 誓言 `ABANDONED`，原文不可再见；玩家可立即新立誓 |

“仍然有效”不是永久豁免。只有当病理窗口先恢复到低于阈值，随后再次满足武装条件时，才允许同一誓言进入新一轮回音。这样避免一次坏周期内的连续轰炸，也保留长期承诺的重量。

## 状态机

```text
NO_OATH
  └─ swear ───────────────────────────────────► DORMANT
                                                    │
                         pathology window qualifies │
                                                    ▼
                                                  ARMED
                                                    │
                              next host load / pending=true
                                                    ▼
                                                  ECHOING
                                                    │
                         keyword verification passed │
                                                    ▼
                                               AWAITING_DECISION
                              ┌─────────────────────┼─────────────────────┐
                              ▼                     ▼                     ▼
                      renew / DORMANT     replace / SUPERSEDED      abandon / ABANDONED
                              │                     │                     │
                              └── new pathology cycle may arm ──────┘       └─ may swear ─► DORMANT
```

`ARMED` 和 `ECHOING` 是工作态，不能由普通游戏页面操作取消。服务端须保证同一玩家同一时刻最多一个待处理回音。

## 前端信息架构

### A. 导航与总览：只提示“存在”，不泄露“内容”

- 侧栏入口由「执念回音」改为「立誓」，保持紫色封印点；有休眠或武装誓言时显示，无数量、无 badge 文案。
- 总览活动流可记录 `誓言已封存`、`回音已回应`，但不得显示原文、关键词、触发次数或病理阈值。
- `ARMED` 期间仍不在导航或总览上提醒，真正的提示只在下次宿主加载时出现。

### B. 立誓页：一张封存卡，而不是状态面板

**无活动誓言**

- 全屏留白、居中单栏，紫灰纸面与弱噪点，避免与病理的冷白病历和法庭的双栏冲突。
- 页面只包含：标题、简短边界说明、范围选择、单句输入框、字符提示、封存按钮。
- 输入框下提示“写具体的行动或底线，不写待办清单”。

**已有活动誓言**

- 不显示原文、创建日期、触发状态或病理数据。
- 仅展示居中的封蜡/封条动画与“有一句话正在沉默中”。
- 说明“它不会出现在这里，也不会催促你”，提供“返回工作台”按钮。

**禁止出现在正式页面的内容**

- 病理窗口评估器、`SEVERE_SLACK` 下拉框、“运行 6h 评估”、模拟触发按钮、`ARMED/DORMANT` 技术状态、`LAST_EVAL`。
- 这些仅可存在于开发环境的独立 debug fixture，不得和玩家页共同渲染。

### C. `EchoInterrupt`：宿主级全屏组件

`EchoInterrupt` 放在 `App` 壳层的路由内容之外，而非 `echo` 页面内。它由 `pending` 状态驱动，覆盖所有路由、移动端导航和弹窗。

组件阶段与可见元素：

| 阶段 | 页面元素 | 可用操作 |
| --- | --- | --- |
| `BLACKOUT` | 黑场、颗粒、扫描线 | 无 |
| `REVEAL` | 誓言原句、低干扰原因说明 | 无 |
| `RECALL` | 模糊原句、关键词输入、提交按钮、失败反馈 | 输入与提交 |
| `DECIDE` | 三个结论动作；改写时展开单句输入 | 选择结论 |
| `RELEASE` | “信号已归档”短暂收束动画 | 自动回到此前路由 |

无障碍要求：打开时将焦点移到主标题；`RECALL` 阶段焦点移至输入框；使用 `aria-live="polite"` 宣读阶段变化；禁止 Escape 和点击遮罩绕过，但不锁死浏览器原生退出方式；遵循 `prefers-reduced-motion` 取消文字逐字和颗粒动画。

### D. 开发与验收入口

- Mock 场景通过 URL fixture 或仅开发构建可见的“回音测试台”进入，例如 `?fixture=echo-armed`；不在生产导航或游戏页展示。
- fixture 覆盖：无誓言、已封存、已武装、关键词失败、仍有效、改写续约、正式放下。
- 移动端中断层保持单列、底部安全区留白，键盘弹起时可滚动到输入框和提交按钮。

## 服务与数据契约

### 最小读取模型

`GET /api/games/echo/state` 只返回能驱动立誓页的非敏感状态：

```json
{ "canSwear": false, "hasActiveOath": true }
```

不返回原文、范围、创建时间、武装状态、评估时间和病理统计。

### 动作

```text
POST /api/games/echo/actions/swear
  { text, scope: "ONE_OFF" | "PRACTICE" | "BOUNDARY" }
  -> 201 { oathId }

GET /api/echo/pending
  -> { pending: false }
  -> { pending: true, oathId, keywordCount: 2 | 3 | 4 }

GET /api/echo/stream?oathId=...
  -> blackout -> voice -> wait_unlock

POST /api/echo/unlock
  { oathId, phrase }
  -> 200 { ok: true }

POST /api/echo/resolve
  { oathId, decision: "RENEW" | "REPLACE" | "ABANDON", replacement?: { text, scope } }
  -> 200 { status }
```

`voice` 仅在已验证 `pending` 的短期会话中发送，且流结束后客户端不应将原文持久化到 localStorage、分析事件或活动流。

### 领域数据

```text
oath
  id, player_id, ciphertext, scope, status,
  armed_cycle_id, last_echo_cycle_id,
  replaced_by, created_at, resolved_at

echo_cycle
  id, oath_id, pathology_window_hash, status,
  armed_at, echoed_at, resolved_at
```

原文加密存储在回音域。`SUPERSEDED` 和 `ABANDONED` 仅保留审计所需的加密记录及状态，不在普通读取模型暴露。

## 信号与触发

| 类型 | 名称 | 用途 |
| --- | --- | --- |
| consume | `pathology.report.issued` | 更新病理日期窗口，触发异步评估 |
| emit | `echo.oath.written` | 记录一次承诺被封存 |
| emit | `echo.triggered` | 记录待处理回音，仅供画像或审计消费 |
| emit | `echo.resolved` | 记录续约、改写或放下的结论 |

回音域读取病历细节只通过 `pathology.query`，不得复制整份病历。计算窗口后保存最小结果和窗口哈希，以支持幂等重算。

## P0 验收

1. 玩家能写入一条有范围的誓言，提交后在所有普通页面均无法找回原文。
2. 无病理报告时，无论用户多久未访问，均不会触发回音。
3. 最近 5 个有病历日期中至少 3 份为 `SEVERE_SLACK` 时，单次异步评估只武装一个回音。
4. 已武装后，下一次任意宿主页面加载在内容可交互前出现全屏中断。
5. 玩家必须输入 2–4 个有效关键词才能进入结论页；答案不能从 `pending` 或普通 `state` 接口取得。
6. 续约在同一病理恶化周期内不会再次触发；恢复后出现新的合格周期时可以再次触发。
7. 改写与放下均结束当前誓言，原文不出现在活动流、导航、客户端持久化或错误日志。

## P1 方向

- 可选的本地音效和“回声强度”视觉主题，默认关闭自动播放。
- 经玩家显式选择后，将脱敏的誓言类别投影到共享语料，提供“有人也在守住类似的事”的匿名共鸣，不展示近邻原文。
- 玩家可导出个人“已放下的承诺”加密档案；导出前需要二次确认，默认仍保持不可见。

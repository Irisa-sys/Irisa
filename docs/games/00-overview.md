# 首发游戏矩阵

七款游戏共享玩家与画像，玩法互不共享 UI。依赖只通过信号。

## 总表

| # | 游戏 | slug | 玩家动作 | 核心循环 | P0 能否独立可玩 |
| --- | --- | --- | --- | --- | --- |
| 1 | 人生决策法庭 | `court` | 提交案由 + 财务/事实，签字结案 | 5 Agent × 3 回合质询 | 能（审计员无数据时说「卷宗空白」） |
| 2 | 项目闹鬼档案 | `haunt` | 接 GitHub webhook / 点幽灵 | diff → 幽灵 → 雷达 | 能（可手动粘贴 diff） |
| 3 | 当代病理诊断书 | `pathology` | 投喂一日罪证 | 诊断 + 药方 + 扣健康度 | 能 |
| 4 | 执念回音壁 | `echo` | 巅峰时刻写誓言 | 休眠 → 背叛判定 → 黑屏拷问 | 能写誓言；触发依赖病理信号，无信号则不响 |
| 5 | 人际关系黑洞拉扯图 | `gravity` | 粘贴聊天 / 写观察日志 | 量化 → 星系图 | 能 |
| 6 | 个人偏见偏振器 | `polarizer` | 输入命题，补论据 | 杠精分身 SSE 对打 | 能（插件同步收藏夹为 P1） |
| 7 | 技术债中央银行 | `bank` | 挂 CI webhook / 看盘 | AST → 本金利息 → K 线 | P0 用简化启发式；JavaParser 全量为 P1 |

法庭是「消费者中枢」：它几乎只读别人的事实。银行与闹鬼是「代码事实生产者」。病理是「生活事实生产者」。回音是「延迟惊吓消费者」。

## 建议实现顺序

见 [路线图](../roadmap.md)。原则：先病理（最简单输入、立刻有画像），再法庭（把画像读出来演戏），再银行/闹鬼（代码侧事实），再回音（延迟彩蛋），最后重力与偏振器（相对独立）。

## 共同验收

每个游戏 P0 必须同时满足：

1. 实现 `game.api` 应用服务，出现在 `/api/games`
2. 至少 1 条登记过的 emit 或 consume
3. 有不可被其他游戏替换的前端语言
4. 账本有至少 1 类 `ledger_entry`
5. 无外部 webhook 时仍可用手动输入玩通一局

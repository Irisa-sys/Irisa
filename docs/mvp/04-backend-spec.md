# 后端总约束 Spec

玩法以 `00-multiverse-archive.md`、`01-decision-court.md`、`02-bias-polarizer.md` 为准。本文件是跨游戏的实现与验收约束。三款游戏各自的命令效果见 `05`、`06`、`07`。

本目录内文档冲突时：产品边界遵循 `00-multiverse-archive.md`；技术约束遵循本文件。

## Problem Statement

玩家需要三款可暂停、可回看、可授权给平行宇宙使用的游戏：人生决策法庭、个人偏见偏振器、平行宇宙档案馆。系统必须把“玩家确认过的事实”和“模型正在生成的过程”分开，把“现实资料”和“平行宇宙经历”分开，并且不能因为检索、流式展示或任务投递把未确认内容写成事实。

当前没有可验收的后端命令面：没有功能模块、没有权威状态、没有授权查询、没有流式运行、没有可取消的生成、也没有不依赖中间件的单测替身。

## Solution

用 Spring Modulith、按功能竖切的模块实现这三款游戏。每个模块默认封闭，只通过 Named Interface 对外。游戏自己落自己的权威资料；全局 LLM 网关只出分段文本和向量；全局 indexing 把各游戏变更异构为推演资料。

玩家通过 REST 发出命令。服务端创建一次运行，游戏调用 LLM 网关拿到分段文本后自己发出过程帧，只有权威数据提交成功后才改变游戏状态。玩家可以取消当前这次生成；已提交内容保留。离线推演不依赖浏览器连接。已确认且仍授权的内容通过各游戏领域事件进入 indexing；游戏模块不感知向量化。

第一期把命令效果用内存适配器单测验收。依赖可以引入，配置文件不写真实中间件地址。

## User Stories

1. As a 玩家, I want 用同一套登录身份进入三款游戏, so that 我的案件、命题和宇宙都属于我。
2. As a 玩家, I want 每条命令都得到明确的接受或拒绝, so that 我知道这次操作有没有生效。
3. As a 玩家, I want 看到角色或事件正在一段一段生成, so that 等待时知道系统在工作。
4. As a 玩家, I want 生成完成前取消这次对话, so that 我不想要的半成品不会留下来。
5. As a 玩家, I want 取消后仍能看到已经确认过的内容, so that 取消不会毁掉整局。
6. As a 玩家, I want 刷新页面后看到的是已提交状态, so that 我不会把流式草稿当成最终结果。
7. As a 玩家, I want 断线后从上次看到的位置继续接收, so that 我不必从头重看整段生成。
8. As a 玩家, I want 未提交成功的半段发言不要出现在回看里, so that 档案里只有完整内容。
9. As a 玩家, I want 按内容范围授权档案馆使用材料, so that 我能保留不想外传的细节。
10. As a 玩家, I want 随时撤回某项授权, so that 后续推演不再使用它。
11. As a 玩家, I want 撤回授权后已经发生的平行宇宙经历保持原样, so that 过去的时间线不会被改写。
12. As a 玩家, I want 未确认的猜测不要进入档案馆, so that 平行宇宙不会把角色假设当成我的事实。
13. As a 玩家, I want 离线推演在我离开页面后继续, so that 我不必一直盯着生成过程。
14. As a 玩家, I want 打开宇宙时看到离线任务的最新进度, so that 我知道它停在哪里。
15. As a 玩家, I want 同一个宇宙不会同时被两路推演改写, so that 时间线保持一条。
16. As a 实现者, I want 游戏内核只依赖本模块端口和共享技术端口, so that 更换 MySQL、检索、消息或模型时不必改玩法规则。
17. As a 实现者, I want 按功能而不是按 controller/service/repository 切模块, so that 一个能力的规则、持久化和适配器住在一起。
18. As a 实现者, I want 档案馆只向 indexing 读取决策资料和画像资料, so that 档案馆领域不出现法庭或偏振器语义。
19. As a 实现者, I want 权威状态以关系数据为准, so that 检索坏了也能重建，游戏状态不丢。
20. As a 实现者, I want 各游戏发本域事件后由 indexing 异构并向量化, so that 玩法代码不感知 embedding，档案馆也不感知来源游戏。
21. As a 实现者, I want LLM 和 Embedding 都走可替换端口, so that 不绑定供应商。
22. As a 实现者, I want 动态配置走各模块内部的配置端口, so that 业务代码不绑定配置中心客户端。
23. As a 实现者, I want 第一期单测不连接任何中间件, so that 命令效果可以在没有外部依赖时验收。
24. As a 实现者, I want 配置文件不写真实中间件地址, so that 本地和仓库里不会出现连接串。
25. As a 实现者, I want Maven 可以引入中间件依赖, so that 以后接真实适配器时不必回头改模块边界。
26. As a 实现者, I want 运行过程帧和领域事件分开, so that 流式展示不会被误当成已提交事实。
27. As a 实现者, I want 宇宙时间线事件和跨模块领域事件使用不同名称, so that 不会把一次推演步骤写成基座事件日志。
28. As a 网关, I want 只转发命令和流式帧, so that 玩法规则留在游戏模块。
29. As a 检索模块, I want 只索引已确认且当前仍授权的内容, so that 相似度结果不会泄漏未授权材料。
30. As a 检索模块, I want 现实资料索引和宇宙专属索引隔离, so that 平行经历不会变成现实资料。
31. As a 模型端口, I want 只返回候选文本或结构化候选, so that 我没有权限改玩家事实、授权或案件状态。
32. As a 玩家, I want 系统在资料不足时停下来问我, so that 关键事实不会被模型补全。
33. As a 玩家, I want 分享链接被撤销后立即失效, so that 我能收回已发出去的只读内容。
34. As a 玩家, I want 删除宇宙后无法再打开它, so that 我的平行经历可以被拿走。
35. As a 测试, I want 用内存适配器验证命令之后记下了什么, so that 验收不依赖外部进程。

## Implementation Decisions

### Spring Modulith

一个 JVM、一个应用。一个功能一个 `@ApplicationModule`，默认封闭。不要按 controller、service、repository 拆包。对外只开 Named Interface。

功能模块：

| 模块 | 公开面 | 职责 |
| --- | --- | --- |
| `identity` | `auth`、`player` | 登录与玩家。无 Modulith 依赖 |
| `llm` | `generation`、`embedding` | 全局模型网关：供应商、用量、分段文本、向量。不知道角色、阶段、SSE 帧名、案件或命题 |
| `game` | `runtime` | 运行标识、命令回执、过程帧形状 |
| `game.court` | `command`、`event` | 法庭权威资料、庭审命令、本域事件 |
| `game.polarizer` | `command`、`event` | 偏振器权威资料、对打命令、本域事件 |
| `indexing` | `materials`、`search` | 监听游戏事件，异构为决策/画像，提供结构化读取和语义检索 |
| `game.archive` | `command` | 宇宙、推演、宇宙 RAG；推演资料只来自 indexing |
| `gateway` | 无对外 Named Interface | REST 命令入口；LiteTopic 过程帧转 SSE |

允许依赖：

```text
identity                 无依赖
llm                      无业务依赖
game                     无业务依赖
game.court               game :: runtime, llm :: generation
game.polarizer           game :: runtime, llm :: generation
indexing                 game.court :: event, game.polarizer :: event, llm :: embedding
game.archive             game :: runtime, llm :: generation, llm :: embedding,
                         indexing :: materials, indexing :: search
gateway                  identity :: auth, game :: runtime,
                         game.court :: command,
                         game.polarizer :: command,
                         game.archive :: command
```

- 游戏自己落自己的权威资料。LLM、消息、仓储适配器放在本模块内部。
- 游戏不依赖 `indexing`。`indexing` 不依赖游戏 `command`。
- `archive` 不依赖 `court` 或 `polarizer` 的任何接口，领域逻辑不出现案件、命题、书记员、反方。
- `gateway` 不依赖 `llm`，不实现玩法。
- 非 MVP 游戏模块不存在。

### 防腐：推演资料

档案馆只认三种推演输入：

- **决策资料**：时点、实际路径、未选路径、限制、授权范围。
- **画像资料**：判断、范围、失效与更新条件、授权范围。结构化结局或 LLM 画像投影后都是这一种。
- **本宇宙经历**：该宇宙已提交的时间线、介入与理由、当前状态。由宇宙 RAG 提供，不进 indexing。

`court` / `polarizer` 在发布本域事件前，把结案或结局译成决策/画像字段。`indexing` 只保存这两种资料。撤回授权后，`materials` 和 `search` 对后续查询立即不可见。

### Indexing 与宇宙 RAG

Indexing 是玩家级、跨宇宙的现实资料面：

- 来源：法庭结案、偏振器结局、授权变更。
- 内容：已确认且仍授权的决策资料、画像资料。
- 用途：创建历史分叉、推演时理解“这个人”。
- 不含：某宇宙的事件正文、我的行动、宇宙补充、当前状态。

宇宙 RAG 留在 `archive` 内部：

- 来源：该宇宙已提交事件、玩家介入与理由、从当前节点生效的补充、当前状态事实。
- 用途：只给这一条时间线后续生成和平行的你决断。
- 优先级：既定经历高于起点设定，高于 indexing 里的现实资料。
- 撤回现实授权不删除宇宙 RAG 中已写入的经历。删除宇宙时这份 RAG 一并消失。
- 不回写 indexing，平行经历不会变成现实画像。
- embedding 走 `llm :: embedding`，避免 `archive` 与 `indexing` 成环。

### 三类不可混用的“事件”

1. **运行过程帧**：一次生成过程中的展示增量。游戏把 LLM 网关的分段文本译成本域帧，发到 LiteTopic，由 gateway 转为 SSE。不代表游戏状态已改变。
2. **领域事件**：留在各游戏的 `:: event`。权威数据提交成功后发布。`indexing` 只监听这些事件。发布前对应状态必须已经可查询。
3. **宇宙时间线事件**：档案馆里一条已经发生的平行经历。它是 `archive` 内部数据，不是跨模块通知，也不是 SSE 帧。

### 权威数据与检索投影

- 权威来源保存：玩家输入与确认、授权与撤回、案件/命题/宇宙状态、庭审与对打记录、宇宙时间线、当前状态事实、推演任务、分享与撤销。
- indexing 检索投影保存：可重建的切片文本、向量、资料类型（决策或画像）、确认状态、授权过滤字段、所属玩家、向量模型标识与维度。不含来源游戏名作为领域概念。
- 宇宙 RAG 投影留在 `archive`，按宇宙隔离。
- 检索投影故障或需要换模型时，从当前仍授权的权威内容重建。检索结果不能单独成为事实来源。
- 模型内部推理不保存。只保存玩家需要回看或确认的输出。
- 未确认内容可以留在本游戏的讨论记录里，但不能进入结案/结局对外材料，也不能进入 indexing。

### 授权

- 授权按内容范围，不按“整局一键全部给出去”作为唯一选项。
- 玩家可随时撤回。撤回立即阻止后续查询、后续推演和后续索引。
- 撤回不改写已经写入的宇宙时间线、已经生成的事件或已经确认的宇宙当前状态。
- 创建宇宙时对本次实际使用的资料做快照，用来解释该宇宙从什么条件起步。快照不等于后续仍可继续读取被撤回的资料。
- indexing 的 `materials` / `search` 必须同时满足：属于当前玩家、内容已确认、授权仍然有效。档案馆只能读到决策资料和画像资料，读不到来源游戏的内部记录。

### 运行、流式与取消

- 一条会触发生成的命令先创建一次运行，并返回运行标识。
- 运行过程帧至少包括：运行标识、序号、类型、内容、发生时间。
- 帧类型至少包括：`started`、`role-delta`、`narrative-delta`、`summary-ready`、`decision-required`、`information-required`、`progress`、`persisted`、`completed`、`failed`、`cancelled`。
- 采用逐段输出，不采用逐字打字机效果。
- 只有权威数据提交成功后才发出 `persisted` / `completed`。
- 前端刷新、重连或重复提交时，以已提交状态为准，不以已经展示过的流式文本为准。
- 取消只取消当前这次流式生成：停止继续生成，停止发送后续增量帧，运行以 `cancelled` 结束。
- 取消后，未提交的半段发言、半个事件、半份整理不写入权威数据。
- 已经 `persisted` 的内容全部保留。取消不等于暂停宇宙、不等于回退阶段、不等于删除案件或命题。
- 取消后，玩家可对同一对象再发新命令，开启新的运行。
- 取消当前生成不停档案馆离线推演。停止离线任务使用暂停或停止任务命令。
- 同一宇宙任意时刻只能有一个推进任务。
- 离线推演由任务消息唤醒，不因关闭页面自动开始，也不因取消当前在线生成而停止。
- 每一步只原子提交一个完整时间线事件。失败的当前步骤不写入；此前完整事件保留；宇宙停在最后一个完整事件。

### 向量化

- 游戏在权威提交成功后发布本域事件，不调用 embedding，不维护 indexing 文档。
- `indexing` 消费游戏事件：检查确认状态和当前授权，再调用 `llm :: embedding` 写入或更新玩家级投影。
- 授权撤回先阻断 `materials` / `search`，再异步将对应投影标记失效或删除。
- `archive` 在本宇宙事件提交成功后更新宇宙 RAG，调用 `llm :: embedding`，不发事件给 indexing。
- 向量记录带模型标识、版本和维度，支持以后重建和切换。第一期单测不连真实向量库。

### 模型

- `llm :: generation` 只回调分段文本和完整结果。游戏把文本译成本域过程帧后自己发 LiteTopic。
- `llm :: embedding` 只把给定文本转为向量。
- 游戏模块在写入权威数据前，必须用本游戏规则校验模型输出：阶段主题、资料权限、未确认内容不得升级为事实、不得改写既定经历、不得替玩家做阶段推进或结案。
- `llm` 不能直接修改玩家身份、授权、案件状态、宇宙状态或现实资料。

### 配置、依赖与第一期范围

- Maven 可以引入 MySQL、ES、Redis、RocketMQ、Apollo 和语言模型相关依赖。
- 配置文件不写真实中间件地址、账号、密钥或连接串。
- 动态配置的生产适配器是 Apollo，放在使用它的模块内部；第一期单测使用内存配置。
- 第一期只完善单测。仓储、检索、消息、模型、配置全部使用内存适配器，不连接任何中间件。 `llm` 和 `indexing` 同样提供内存实现。
- 真实中间件适配器可以后补，但不能破坏本文件已经钉死的端口和命令效果。

## Testing Decisions

好的测试只断言命令之后可观察的结果：状态、已提交记录、indexing 对后续查询的可见性、运行结束方式。不断言表结构、SDK 调用、SQL、检索实现或配置中心客户端。

主测试缝是各游戏命令接口。支撑缝是本域事件发布、indexing 的 materials/search、宇宙 RAG、llm 端口、运行过程帧和取消。HTTP/SSE 只测命令能进入游戏模块、过程帧能转出、能按序号续流；不把路径或事件名当成玩法规则。

Modulith 测试必须 `ApplicationModules.verify()`：依赖图符合本文件，且不存在非 MVP 游戏模块。

第一期单测必须使用内存适配器，不连接 MySQL、ES、Redis、RocketMQ、Apollo 或外部语言模型。

必须覆盖：

- 未确认内容不会出现在 indexing 的 materials 或 search 中。
- 撤回授权后，后续 materials/search 和后续推演看不到该内容；已写入的宇宙经历仍在。
- 取消当前生成后，权威数据没有半段记录，已提交记录仍在。
- 生成失败时，失败的当前步骤不落库。
- 同一宇宙不能同时存在两个推进任务。
- indexing 在未确认或已撤回时不建立有效投影。
- archive 命令接口只看到决策资料和画像资料，看不到来源游戏内部记录。
- 游戏内核在没有真实中间件时仍能完成上述命令效果。

现有仓库几乎没有业务单测，本批 spec 的测试从游戏命令接口新建，不沿用旧合同或旧玩法测试假设。

## Out of Scope

- 从既有宇宙历史节点 Fork 新宇宙。
- 系统推送通知。
- 改写已经发生的宇宙经历或现实结果。
- 本目录未纳入的其他玩法。
- 把流式草稿、检索命中或模型推理升级为现实事实。
- 第一期连接真实中间件或在配置文件中写入真实连接信息。
- 绑定具体模型供应商、向量维度或部署方式。

## Further Notes

`05`、`06`、`07` 只补充本游戏命令和本游戏可观察效果。跨游戏的运行、授权、indexing、宇宙 RAG、取消、防腐和单测替身以本文件为准，三份游戏 spec 不重复定义另一套机制。
